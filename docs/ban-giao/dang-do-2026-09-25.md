## 6. Plan #28 — hàng đợi và provisioning đầu–cuối (đã xong P1–P7)

- Hàng đợi `pg-boss` (`jobs/boss.ts`, schema `PGBOSS_SCHEMA`, polling, qua
  `DATABASE_URL_DIRECT`) + đối soát 5 phút một lần (`jobs/reconcile.ts`); worker chạy trong
  tiến trình Service 1 (`jobs/provision.job.ts`), gắn ở `index.ts`, tắt êm theo thứ tự hàng
  đợi rồi database.
- Job PROVISION: NETWORK → CLUSTER → CLUSTER_ACCESS (bootstrap §12.2) → DOMAINS (theo bậc,
  binding xuống bảng) → DONE; bù trừ XUYÊN pha (gỡ domain trước, rồi cloud ngược thứ tự);
  hủy hợp tác; tiếp quản khi worker chết; chạy lại từ ERROR đóng chu kỳ sổ.
- HTTP: `GET /preview`, `POST /provision` (Idempotency-Key, 428), `GET /jobs`,
  `GET /jobs/:jobId`, SSE `…/stream`, `POST …/cancel`; đổi credential khi có job ⇒ 409.
- Portal: trang **Hạ tầng** (`/infra`), bước 4–5 của wizard.
- **Cấu hình mới bắt buộc để provisioning:** `UDP_EGRESS_CIDRS` (CIDR IPv4 egress của UDP,
  phân tách dấu phẩy). Thiếu thì xem trước báo lý do chặn, không mở API cluster ra
  `0.0.0.0/0`.
- Nợ kiểm chứng giữ lại: `I32-cluster` (mở rộng: transport + TokenRequest + bootstrap trên
  cluster thật), `I31-*` (lưới trên cloud thật).
